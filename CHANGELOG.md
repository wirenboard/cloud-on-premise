# Changelog

Все значимые изменения в проекте фиксируются в этом файле.

## [2.1.0] - 2026-12-01

### Перед обновлением

- С 2.0.1 обновляются один раз командой `git pull && make update`, дальше достаточно `make update`: он сам скачивает файлы и образы выпуска, делает дамп основной базы (хранятся три последних) и только потом переключает версию.
- Дамп не покрывает базу метрик, а после обновления TimescaleDB версия 2.0.1 с ней не запустится. Для возможности отката сделайте снимок сервера или копию томов (README, «Обновление»).
- Логины, отличающиеся только регистром, останавливают обновление до любых изменений: переименуйте или удалите один логин из каждой пары в админке.
- Контроллер добавляется, только если сервер облака отправляет метрики на `on-premise-metrics.wirenboard.cloud`. Прокси для выхода в интернет — `HTTPS_PROXY` в `.env`.
- Образы бэкенда собраны на Debian 13. Если письма перестанут уходить с ошибкой SSL, почтовый сервер использует устаревшее шифрование: обновите его или смените `EMAIL_HOST`.
- `make run` и `make restart` отказывают, пока на сервере есть контейнеры другой версии облака; `make stop` больше не удаляет контейнеры.

### После обновления

- Все пользователи один раз входят заново, открытые через туннель вкладки веб-интерфейса и SSH контроллера нужно перезагрузить.
- Веб-интерфейс работает только по адресу `https://${ABSOLUTE_SERVER}` и не открывается во фрейме на других сайтах.
- Незавершённые запросы смены почты удаляются.
- Ключ карт `CARTO_API_KEY`, тексты письма-приглашения и брендинг один раз переносятся из `.env` в админку и дальше меняются там. Ключ, заданный только фронтенду через `docker-compose.override.yml`, не переносится: задайте его в админке (Настройки → Карты).
- Хранилище файлов MinIO заменено на SeaweedFS без переноса данных: диагностические архивы запросите заново. Старый том удаляется вручную: `docker volume rm <project>_minioData`.
- Если `MINIO_ROOT_USER` и `MINIO_ROOT_PASSWORD` не заданы в `.env`, обновление записывает туда случайные ключи.
- Лишние организации Grafana удаляются при обновлении. Учётные записи Grafana, сломанные сменой почты, чинит `docker compose exec -w /src backend uv run --no-dev ./manage.py fix_grafana_logins --apply`.

### Безопасность

- Обновлены Traefik 3.7.16, Grafana 12.4.14, Redis 7.4.12, PostgreSQL 17.11 и TimescaleDB 2.30.2 в базе метрик, Django 5.2 LTS и зависимости; образы пересобраны без уязвимой библиотеки brotli.
- Пользователь Grafana не может выполнить код на сервере базы метрик и узнать данные чужих организаций через ошибки запросов, статистику базы и EXPLAIN.
- Агент не может выдать себя за другой контроллер подменой заголовка. Сброс пароля Grafana и её метрики `/metrics` закрыты снаружи.
- Страница контроллера, открытая через туннель, не может выполнять запросы к API облака от имени посетителя.
- Ключ доступа к туннелю действует только на адресе своего туннеля.
- Перебор пароля и кода 2FA блокирует вход с письмом владельцу (пределы 2FA — `TOTP_*`). Вход в админку с 2FA всегда требует код, смена пароля ограничена по частоте.
- Смена почты требует пароль и уведомляет старый адрес; смена пароля или почты завершает все сессии.
- Приём приглашения больше не даёт войти в существующий аккаунт без пароля и 2FA.
- Пользователь, удалённый из организации или отключённый, сразу теряет открытые через туннель веб-интерфейс и SSH контроллера.
- По серийнику больше нельзя узнать, есть ли в облаке чужой контроллер. Диагностические архивы не лежат в публичном бакете. Выгрузка в CSV экранирует формулы.

### Исправлено

- Веб-интерфейс контроллера через туннель выкидывал на вход из-за посторонней куки на родительском домене (например, Яндекс Метрики).
- Туннель не восстанавливался после того, как облако отключало его подключение.
- Экран «500 Ошибка сервера» при перезапуске бэкенда держался до перезагрузки страницы.
- Участник организации с обязательной 2FA без включённой 2FA не мог выйти из организации.
- Двойной клик отправлял несколько приглашений.
- Telegraf терял пачку метрик из-за лишнего тега или символа NUL.
- Поиск по списку контроллеров ломался на спецсимволах.
- Веб-консоль не скачивала и не загружала файлы с кириллицей в имени.
- Лог бэкенда засорялся трейсбэками о сервисе лицензий и предупреждениями GeoIP.
- Письма называли продукт Wiren Board Cloud вместо названия из админки.
- Шаги знакомства с интерфейсом не переводились при смене языка.

### Изменено

- Логотип, иконки, ключ карт CARTO и языки интерфейса настраиваются в админке. Название и цвет из админки применяются и в веб-консоли.
- Шрифты интерфейса входят в сборку, Google Fonts не нужен. Поиск адреса не передаёт сервису OpenStreetMap почту Wiren Board.
- Выгрузка контроллеров содержит до 5000 строк и время последней связи агента.
- Ошибка открытия туннеля называет причину.
- Письма сброса пароля и 2FA приходят на языке пользователя.
- Терминал веб-консоли после обрыва связи возвращается в ту же сессию.
- Веб-консоль и туннели видят настоящий IP-адрес пользователя, а не адрес прокси.

### Добавлено

- Интервал отправки метрик для каждого контроллера: от 60 до 240 секунд.
- Письмо владельцу при входе с нового устройства.
- Запасные почтовые серверы `EMAIL_FALLBACK_URLS`, прокси `HTTPS_PROXY` и `NO_PROXY`, таймауты веб-консоли (`WS_RESUME_*`, `SSH_CHANNEL_TIMEOUT`, `SFTP_TIMEOUT`, `DELETE_TIMEOUT`) в `.env`.

## [2.0.1] - 2026-09-30

### Исправлено

- `make update` больше не останавливает облако, если образы не удалось скачать.
- Версия облака в интерфейсе и админке могла показываться с суффиксом `-testing`.
- Подключение к контроллеру через туннель обрывалось, когда туннель временно ограничивал частоту запросов.

### Изменено

- Образы MinIO и mc удалены с Docker Hub, поэтому теперь они берутся из зеркала `ghcr.io/wirenboard/on-premise`.
- Карты сервиса CARTO стали требовать API-ключ. Добавить его теперь можно переменной `CARTO_API_KEY` в `.env`, как получить ключ — в README, раздел «Карта контроллеров».

### Добавлено

- Ссылка «Документация» в футере открывает страницу на языке интерфейса. Английская ссылка задаётся переменной `SERVICE_DOCS_URL_EN`.

## [2.0.0] - 2026-08-20

> Мажорный релиз с несовместимыми изменениями. Порядок обновления —
> в [`RELEASE_NOTES_2.0.md`](migration/RELEASE_NOTES_2.0.md).

### Добавлено

- Доступ к веб-интерфейсам сервисов контроллера прямо из облака: Node-RED, Home Assistant, Zigbee2MQTT и любой свой сервис на произвольном порту открываются по ссылке через защищённый туннель — без VPN, проброса портов и белого IP.
- Метрики контроллеров: дашборды Grafana в разрезе организации и оповещения по своим правилам (свободное место, температура, нагрузка) с письмами на почту.
- Двухфакторная аутентификация с кодами восстановления и требованием 2FA для всей организации; опасные действия подтверждаются кодом.
- Управление сессиями: список устройств с браузером, адресом, страной и городом; завершение чужой сессии одной кнопкой.
- Перенос контроллеров между организациями — с подтверждением принимающей стороной и возможностью отменить запрос.
- Веб-консоль на телефоне: панель спецклавиш, залипающие Ctrl и Alt, полноэкранный режим. В файловом менеджере — удаление и загрузка файлов до 350 МБ.

### Изменено

- **Вход по email вместо логина.** Email стал обязательным и уникальным, при регистрации подтверждается письмом. Учётные записи без почты или с несовпадающим логином приводятся в порядок при обновлении — данные не теряются.
- Открытие туннеля к контроллеру стало заметно быстрее.

### Инфраструктура и развёртывание

- **Сертификат должен покрывать ещё и `*.apps.<домен>`** — без него облако не стартует. Нужна и DNS-запись: на этом поддомене живут веб-сервисы контроллеров.
- **Обновление одной командой `make upgrade`:** обязательный бэкап, проверка учётных записей на совместимость с новой схемой и только потом миграция. Пока данные не в порядке, миграция не запускается.
- **Хранилище метрик переехало с InfluxDB на TimescaleDB.** Накопленная история в новые графики не переносится: при обновлении она сохраняется в резервную копию рядом.
- **База данных работает в надёжном режиме.** Раньше запись велась с отключёнными гарантиями сохранности и без автоочистки — от такой конфигурации отключение питания могло стоить базы, а таблицы со временем распухали.
- **Почтовые настройки задаются отдельными переменными** (`EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`), а `EMAIL_ENABLED` нужно задать явно. Старые переменные `make upgrade` переносит сам.
- **Стек вырос** — добавились TimescaleDB, Grafana, Telegraf и два фоновых обработчика. Требования к серверу прежние: параллелизм фоновых задач по умолчанию рассчитан на сотню контроллеров и настраивается переменными в обе стороны.
- Появились настройки под своё железо и политику хранения: срок хранения метрик, параллелизм фоновых задач, геолокация сессий (см. `.env.example`).

## [1.5.0] - 2026-07-28

### Добавлено

- Переопределение ссылки «сайт компании» в футере веб-интерфейса через переменные `FOOTER_SITE_URL`, `FOOTER_SITE_LABEL_RU`, `FOOTER_SITE_LABEL_EN` (см. `.env.example`, секция Branding). Если переменные не заданы, используются значения Wiren Board по умолчанию.

### Изменено

- Заголовок вкладки браузера теперь берётся из `SERVICE_NAME`: для ребрендинга достаточно задать одну переменную. Переменная `HTML_TITLE` упразднена — если она задана в `.env`, она просто игнорируется.

### Безопасность

- Туннельный авторизатор: закрыты два обхода авторизации по `tunnel_key`. Модуль nginx `auth_jwt` теперь собирается из форка `wirenboard/ngx-http-auth-jwt-module` (2.0.2-wb3): зафиксирован алгоритм подписи JWT и вычищаются подменные claim-заголовки клиента.

## [1.4.0] - 2026-07-25

### Добавлено

- Переопределение названия продукта и ссылок в веб-интерфейсе через переменные окружения `SERVICE_NAME`, `HTML_TITLE`, `SERVICE_STATUS_URL`, `SERVICE_DOCS_URL` (см. `.env.example`, секция Branding). Если переменные не заданы, используются значения Wiren Board по умолчанию.

- Переопределение цвета основной кнопки через переменную `PRIMARY_COLOR` (hex) в веб-интерфейсе и веб-консоли. Если переменная не задана, используется цвет по умолчанию.

## [1.3.0] - 2026-06-09

### Добавлено

- Полное отключение отправки email через переменную `EMAIL_ENABLED=False`: переменные `EMAIL_*` перестают быть обязательными, приглашения и сброс пароля выполняются через административную панель.
- Действие в административной панели для генерации одноразовой ссылки сброса пароля (работает без email).
- Документация: внешний reverse-proxy перед облаком (nginx и Traefik, L4 TCP passthrough); сетевая схема, порты и правила фаервола (`doc/SECURITY_NETWORK.md`, RU/EN); раздел об административной панели; развёртывание в локальной сети без публичного доступа (публичный сертификат + внутренний DNS).

### Изменено

- `EMAIL_ENABLED=True` теперь явно присутствует в `.env.example` (основная секция). Для существующих инсталляций ничего не меняется: если переменная не задана, отправка email включена, как и раньше.

### Исправлено

- Падение бэкенда на старте при пустом `EMAIL_URL`.
- Пример конфигурации nginx (маршрутизация по SNI): регулярное выражение не матчило корневой домен облака.
- Документация внешнего reverse-proxy: уточнено, что `your-domain.com` — это полный hostname облака, включая поддомен (значение `ABSOLUTE_SERVER`); для Traefik-примера (кейс C) добавлено предупреждение об экранировании бэкслешей в YAML-кавычках (ошибка `unknown escape character` приводит к отдаче default-сертификата вместо passthrough).
