# Changelog

Все значимые изменения в проекте фиксируются в этом файле.

## [Unreleased]

### Перед обновлением

- Обновление идёт через утилиту `wb-onprem`: она проверяет установку, делает бэкап томов, переключает версию и откатывает её при сбое. `make update` вызывает утилиту, а без неё отказывает со ссылкой на её выпуски. `make run` и `make restart` отказывают, пока на сервере есть контейнеры другой версии облака, в том числе остановленные: `make stop` их больше не удаляет. Если контейнеры удалены, а база осталась, `make run` и `make restart` сверяют версию файлов с версией последнего запуска; на установке, где её ещё не записывали (2.0.1 и раньше), они отказывают и предлагают поднять прежнюю версию её файлами и запустить `make update`.
- Логины пользователей становятся уникальными без учёта регистра. Если на установке есть логины, отличающиеся только регистром, обновление останавливается до любых изменений: переименуйте или удалите один логин из каждой пары в админке и запустите обновление снова.
- В бесплатной (FREE) версии, а другой пока нет, добавить контроллер можно, только если сервер облака отправляет метрики на `on-premise-metrics.wirenboard.cloud`: при закрытом выходе туда облако отказывает в добавлении. Ответ сервера метрик с ошибкой добавлению не мешает, уже добавленные контроллеры работают как раньше. Если выход в интернет идёт через прокси, задайте его переменной `HTTPS_PROXY` в `.env`.
- Образы бэкенда собраны на Debian 13 и Python 3.11 с актуальными исправлениями безопасности и стали вдвое меньше. Если после обновления письма не уходят с ошибкой SSL, почтовый сервер использует устаревшее шифрование (сертификат с подписью SHA-1 или старое согласование TLS): обновите его или укажите другой сервер в `EMAIL_HOST` файла `.env`.

### После обновления

- Все пользователи один раз входят заново: куки входа переименованы.
- Веб-интерфейс работает только по адресу `https://${ABSOLUTE_SERVER}`. Если открыть его по IP-адресу или другому имени, вход и любые изменения получают отказ 403.
- Открытые через туннель вкладки веб-интерфейса и SSH контроллера один раз перезагружаются: ключ доступа к туннелю привязан к сессии облака, старые ключи недействительны.
- Облако не открывается во фрейме (iframe) на других сайтах.
- Незавершённые запросы смены почты удаляются: смену нужно запросить заново.
- Если несколько пользователей были привязаны к одной учётной записи Grafana, привязка снимается, и облако заново подключает их к метрикам организации.
- Ключ карт `CARTO_API_KEY` и тексты письма-приглашения (`INVITE_EMAIL_SUBJECT`, `INVITE_EMAIL_BODY`) один раз переносятся из `.env` в админку при первом запуске 2.1.0 и дальше меняются там. Переменные брендинга из `.env` тоже копируются в админку (Настройки → Брендинг); ссылку в футере, ссылки на документацию и страницу статуса веб-интерфейс берёт из `.env`, как в 2.0.1.
- Ключ карт переносится только из `CARTO_API_KEY` в `.env`. Если в 2.0.1 ключ получал один фронтенд, например через `docker-compose.override.yml`, после обновления карты и поиск адреса скрыты, пока ключ не задан в админке (Настройки → Карты).
- Хранилище файлов MinIO заменено на SeaweedFS, его данные не переносятся. Диагностический архив контроллера, запрошенный до обновления, запросите заново.
- Контейнеры `minio` и `minio-client` при обновлении удаляются, их том остаётся. Если диагностические архивы в нём не нужны, удалите его: имя покажет `docker volume ls -q --filter name=minioData`, удалит `docker volume rm <имя>`.
- Если ключи `MINIO_ROOT_USER` и `MINIO_ROOT_PASSWORD` в `.env` не заданы, `make generate-env` записывает туда случайные (цель `make generate-s3-keys`). На установке, где действовали ключи по умолчанию, они сменятся при обновлении; заданные ключи не меняются.
- После смены почты пользователь не мог открыть метрики: логин в Grafana оставался старым. Логин меняется вместе с почтой, а учётные записи, затронутые раньше, чинит команда `docker compose exec -w /src backend uv run --no-dev ./manage.py fix_grafana_logins --apply`; без `--apply` она только показывает, что исправит.

### Безопасность

- Traefik обновлён до 3.7.16 (CVE-2026-32305, CVE-2026-71324). Заголовки с символами, кроме букв, цифр и дефиса, отбрасываются: агент не может выдать себя за другой контроллер подменой заголовка с сертификатом. Через туннели HTTP такие заголовки тоже не проходят.
- Сброс пароля Grafana клиентов можно было вызвать в обход запрета через `%2F`, повтор слешей или другой регистр, а метрики самой Grafana (`/metrics`) были открыты всем. Оба пути закрыты.
- Grafana обновлена до 12.4.14, Redis — до 7.4.12. Запросы к Grafana с телом ограничены: до 4 МБ на вход, до 30 одновременно с одного IP-адреса.
- База метрик обновлена до PostgreSQL 17.11 и TimescaleDB 2.30.2: закрыты уязвимости PostgreSQL, через которые пользователь с доступом к Grafana мог выполнить код на сервере базы. Расширение TimescaleDB обновляется само при запуске; вернуться на 2.0.1 после этого можно только из бэкапа тома метрик вместе со старым образом.
- Пользователь Grafana с доступом к метрикам своей организации видел строки чужих организаций в тексте ошибки запроса и мог читать статистику базы метрик (счётчики прочитанных строк по таблицам). Закрыто.
- Пользователю Grafana закрыты EXPLAIN и вывод плана запроса через `debug_print_*`, временные объекты в базе метрик и подключение к `template1`.
- Страница контроллера, открытая через туннель, могла выполнять запросы к API облака от имени посетителя. Изменяющие запросы с чужим `Origin` получают отказ, куки входа не передаются поддоменам.
- Смена почты требует текущий пароль, на старый адрес приходят письма о запросе и о смене. После сброса пароля, любой смены пароля (в том числе из админки и командой `changepassword`) и смены почты завершаются все сессии пользователя.
- Пароль можно было перебирать с разных адресов. После 50 неверных паролей за час вход в аккаунт блокируется на час, владельцу приходит письмо; восстановление пароля снимает блокировку сразу.
- Код 2FA можно было перебирать. Неверные коды считаются по пользователю: после 5 неудач ввод кодов закрыт на 15 минут, каждая следующая блокировка вдвое длиннее (до 4 часов), владельцу приходит письмо. Пределы задают переменные `TOTP_FAILURE_LIMIT`, `TOTP_LOCKOUT_TIME` и `TOTP_MAX_LOCKOUT_TIME`.
- Сотрудник с 2FA мог войти в админку без кода, добавив пробел к логину. Вход в админку с 2FA требует код каждый раз.
- Смена пароля ограничена: 5 попыток в минуту и 20 в сутки.
- Приём приглашения в организацию выдавал вход в существующий аккаунт без пароля и 2FA, а запрос без токена приглашения отвечал ошибкой 500. Закрыто; пароль при приёме приглашения проверяется по тем же правилам, что при регистрации.
- Через привязку контроллеров к группе и отвязку можно было узнать, есть ли в облаке контроллер с чужим серийником. На чужой серийник ответ тот же, что на несуществующий: «Контроллеры не найдены». Отвязывать контроллеры от групп демо-пользователю нельзя.
- Пользователь, которого удалили из организации, отключили или удалили, а также участник организации, из которой передали контроллер, сохранял открытый через туннель веб-интерфейс и SSH контроллера. Доступ пропадает сразу, у остальных пользователей контроллера соединение переподключается.
- Хранилище файлов отдавало диагностические архивы из публичного бакета. Бакет SeaweedFS закрыт ключами, архив скачивается только по подписанной ссылке.
- Образы пересобраны без уязвимой библиотеки brotli (CVE-2026-111497): авторизатор туннелей на nginx 1.30.6, фронтенд и веб-консоль на Node 24.22.3. В образе бэкенда brotli 1.2.0 остаётся внутри Pillow: бэкенд открывает через Pillow только PNG и ICO брендинга, уязвимый декодер шрифтов не вызывается.
- Django обновлён до 5.2 LTS, уязвимые зависимости бэкенда и веб-консоли обновлены.
- В выгрузке контроллеров в CSV значения, начинающиеся с `=`, `+`, `-` или `@`, экранируются апострофом, чтобы табличный редактор не выполнил их как формулу.

### Исправлено

- Веб-интерфейс контроллера через туннель выкидывал на форму входа после верного пароля, если у домена облака была посторонняя кука с `id` в конце имени (например, `_ym_uid` Яндекс Метрики на родительском домене).
- Туннель контроллера не восстанавливался, если облако отключило его подключение (выход, зависание, админка): новое подключение не выдавалось.
- Экран «500 Ошибка сервера» при перезапуске бэкенда держался до перезагрузки страницы. Сервис сам повторяет запрос и открывает страницу.
- Участник организации с обязательной 2FA, у которого 2FA не включена, не мог ни открыть список организаций, ни выйти из неё.
- Двойной клик в окне приглашения отправлял несколько приглашений с разными ссылками.
- Некорректные запросы к API отвечали ошибкой 500, а кнопка «Скачать диагностику» после завершения сессии молча не срабатывала.
- Telegraf отбрасывал всю пачку метрик, если контроллер присылал лишний тег, числовое значение или символ NUL, и менял структуру таблицы метрик. Записываются только host, topic и value, NUL вырезается. При недоступной базе метрик на старте Telegraf повторяет подключение.
- Поиск по списку контроллеров ломал таблицу на спецсимволах, а ссылка с поиском открывалась с неверными галочками «искать по».
- В веб-консоли файлы с кириллицей в имени не скачивались и не загружались. Терминал после сворачивания браузера или обрыва сети переподключается к той же сессии, папки со множеством симлинков открываются быстрее.
- Лог бэкенда на каждый запрос писал трейсбэк о недоступном сервисе лицензий, а предупреждение об отсутствии базы GeoIP повторялось при каждом входе.
- Письма о приглашении, передаче контроллера и подтверждении регистрации называли продукт Wiren Board Cloud, даже если в админке задано другое название.

### Изменено

- Логотип и иконки можно загрузить из админки (Настройки → Брендинг): файлы сохраняются в каталог `branding/`.
- Название продукта и основной цвет из админки применяются и на страницах SSH и файлового менеджера. `SERVICE_NAME` и `PRIMARY_COLOR` из `.env` остаются запасными: они действуют, пока в админке поле пустое или бэкенд недоступен с момента запуска веб-консоли.
- Ключ карт CARTO задаётся в админке (Настройки → Карты). Без ключа карты и поиск адреса скрыты.
- Поиск адреса не передаёт сервису геокодирования OpenStreetMap почту Wiren Board.
- Шрифты интерфейса входят в сборку фронтенда и не загружаются с Google Fonts.
- Хранилище файлов MinIO заменено на SeaweedFS: образы MinIO сняты с Docker Hub и не получают исправлений безопасности. Образ берётся из зеркала `ghcr.io/wirenboard/on-premise`.
- Список контроллеров выгружается в файл целиком, до 5000 контроллеров; если их больше, файл приходит с предупреждением.
- Ошибка открытия туннеля называет причину: туннель не подключён, контроллер не ответил или сервис на контроллере вернул ошибку.
- Письма сброса пароля и 2FA приходят на языке того, кто их запросил.

### Добавлено

- Интервал отправки метрик настраивается для каждого контроллера: от 60 до 240 секунд, по умолчанию 120.
- Языки интерфейса и язык по умолчанию выбираются в админке (Настройки → Языки интерфейса).
- Письмо владельцу аккаунта при входе с нового устройства.
- Последняя колонка выгрузки контроллеров — время последней связи агента.
- Запасные почтовые серверы: если основной не принимает письмо, оно уходит через следующий из `EMAIL_FALLBACK_URLS`.
- Прокси для выхода в интернет: `HTTPS_PROXY` и `NO_PROXY` в `.env`; сервисы облака обращаются друг к другу мимо прокси.
- Настройки веб-консоли в `.env`: возврат терминала после обрыва связи (`WS_RESUME_*`), и таймауты SSH, SFTP и удаления файлов (`SSH_CHANNEL_TIMEOUT`, `SFTP_TIMEOUT`, `DELETE_TIMEOUT`).

## [2.0.0] - 2026-08-20

> Мажорный релиз с несовместимыми изменениями. Порядок обновления —
> в [`RELEASE_NOTES_2.0.md`](migration/RELEASE_NOTES_2.0.md).

### Добавлено

- Доступ к веб-интерфейсам сервисов контроллера прямо из облака: Node-RED, Home Assistant, Zigbee2MQTT и любой свой сервис на произвольном порту открываются по ссылке через защищённый туннель — без VPN, проброса портов и белого IP.
- Метрики контроллеров: дашборды Grafana в разрезе организации и оповещения по своим правилам (свободное место, температура, нагрузка) с письмами на почту.
- Двухфакторная аутентификация с кодами восстановления и требованием 2FA для всей организации; опасные действия подтверждаются кодом.
- Управление сессиями: список устройств с браузером, адресом, страной и городом; завершение чужой сессии одной кнопкой.
- Перенос контроллеров между организациями — с подтверждением принимающей стороной и возможностью отменить запрос.
- Веб-консоль на телефоне: панель спецклавиш, залипающие Ctrl и Alt, полноэкранный режим. В файловом менеджере — удаление и загрузка файлов до 350 МБ.

### Изменено

- **Вход по email вместо логина.** Email стал обязательным и уникальным, при регистрации подтверждается письмом. Учётные записи без почты или с несовпадающим логином приводятся в порядок при обновлении — данные не теряются.
- Открытие туннеля к контроллеру стало заметно быстрее.

### Инфраструктура и развёртывание

- **Сертификат должен покрывать ещё и `*.apps.<домен>`** — без него облако не стартует. Нужна и DNS-запись: на этом поддомене живут веб-сервисы контроллеров.
- **Обновление одной командой `make upgrade`:** обязательный бэкап, проверка учётных записей на совместимость с новой схемой и только потом миграция. Пока данные не в порядке, миграция не запускается.
- **Хранилище метрик переехало с InfluxDB на TimescaleDB.** Накопленная история в новые графики не переносится: при обновлении она сохраняется в резервную копию рядом.
- **База данных работает в надёжном режиме.** Раньше запись велась с отключёнными гарантиями сохранности и без автоочистки — от такой конфигурации отключение питания могло стоить базы, а таблицы со временем распухали.
- **Почтовые настройки задаются отдельными переменными** (`EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`), а `EMAIL_ENABLED` нужно задать явно. Старые переменные `make upgrade` переносит сам.
- **Стек вырос** — добавились TimescaleDB, Grafana, Telegraf и два фоновых обработчика. Требования к серверу прежние: параллелизм фоновых задач по умолчанию рассчитан на сотню контроллеров и настраивается переменными в обе стороны.
- Появились настройки под своё железо и политику хранения: срок хранения метрик, параллелизм фоновых задач, геолокация сессий (см. `.env.example`).

## [1.5.0] - 2026-07-28

### Добавлено

- Переопределение ссылки «сайт компании» в футере веб-интерфейса через переменные `FOOTER_SITE_URL`, `FOOTER_SITE_LABEL_RU`, `FOOTER_SITE_LABEL_EN` (см. `.env.example`, секция Branding). Если переменные не заданы, используются значения Wiren Board по умолчанию.

### Изменено

- Заголовок вкладки браузера теперь берётся из `SERVICE_NAME`: для ребрендинга достаточно задать одну переменную. Переменная `HTML_TITLE` упразднена — если она задана в `.env`, она просто игнорируется.

### Безопасность

- Туннельный авторизатор: закрыты два обхода авторизации по `tunnel_key`. Модуль nginx `auth_jwt` теперь собирается из форка `wirenboard/ngx-http-auth-jwt-module` (2.0.2-wb3): зафиксирован алгоритм подписи JWT и вычищаются подменные claim-заголовки клиента.

## [1.4.0] - 2026-07-25

### Добавлено

- Переопределение названия продукта и ссылок в веб-интерфейсе через переменные окружения `SERVICE_NAME`, `HTML_TITLE`, `SERVICE_STATUS_URL`, `SERVICE_DOCS_URL` (см. `.env.example`, секция Branding). Если переменные не заданы, используются значения Wiren Board по умолчанию.
- Веб-консоль (webssh) теперь тоже использует брендовые ассеты из директории `branding/`: логотип и иконки подменяются так же, как в основном фронтенде.
- Веб-консоль (webssh) переопределяет название в заголовке вкладки и окне входа через `SERVICE_NAME`, а ссылку логотипа и редирект при ошибке туннеля — на домен инсталляции (`ABSOLUTE_SERVER`) вместо `wirenboard.cloud`.
- Переопределение цвета основной кнопки через переменную `PRIMARY_COLOR` (hex) в веб-интерфейсе и веб-консоли. Если переменная не задана, используется цвет по умолчанию.

## [1.3.0] - 2026-06-09

### Добавлено

- Полное отключение отправки email через переменную `EMAIL_ENABLED=False`: переменные `EMAIL_*` перестают быть обязательными, приглашения и сброс пароля выполняются через административную панель.
- Действие в административной панели для генерации одноразовой ссылки сброса пароля (работает без email).
- Документация: внешний reverse-proxy перед облаком (nginx и Traefik, L4 TCP passthrough); сетевая схема, порты и правила фаервола (`doc/SECURITY_NETWORK.md`, RU/EN); раздел об административной панели; развёртывание в локальной сети без публичного доступа (публичный сертификат + внутренний DNS).

### Изменено

- `EMAIL_ENABLED=True` теперь явно присутствует в `.env.example` (основная секция). Для существующих инсталляций ничего не меняется: если переменная не задана, отправка email включена, как и раньше.

### Исправлено

- Падение бэкенда на старте при пустом `EMAIL_URL`.
- Пример конфигурации nginx (маршрутизация по SNI): регулярное выражение не матчило корневой домен облака.
- Документация внешнего reverse-proxy: уточнено, что `your-domain.com` — это полный hostname облака, включая поддомен (значение `ABSOLUTE_SERVER`); для Traefik-примера (кейс C) добавлено предупреждение об экранировании бэкслешей в YAML-кавычках (ошибка `unknown escape character` приводит к отдаче default-сертификата вместо passthrough).
