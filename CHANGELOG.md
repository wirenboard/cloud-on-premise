# Changelog

Все значимые изменения в проекте фиксируются в этом файле.

## [2.0.0] - 2026-08-12

> Мажорный релиз с несовместимыми изменениями. Порядок обновления —
> в [`RELEASE_NOTES_2.0.md`](RELEASE_NOTES_2.0.md).

### Добавлено

- Доступ к веб-интерфейсам сервисов контроллера прямо из облака: Node-RED, Home Assistant, Zigbee2MQTT и любой свой сервис на произвольном порту открываются по ссылке через защищённый туннель — без VPN, проброса портов и белого IP.
- Метрики контроллеров: дашборды Grafana в разрезе организации и оповещения по своим правилам (свободное место, температура, нагрузка) с письмами на почту.
- Двухфакторная аутентификация с кодами восстановления и требованием 2FA для всей организации; опасные действия подтверждаются кодом.
- Управление сессиями: список устройств с браузером, адресом, страной и городом; завершение чужой сессии одной кнопкой.
- Перенос контроллеров между организациями — с подтверждением принимающей стороной и возможностью отменить запрос.
- Веб-консоль на телефоне: панель спецклавиш, залипающие Ctrl и Alt, полноэкранный режим. В файловом менеджере — удаление и загрузка файлов до 350 МБ.

### Изменено

- **Вход по email вместо логина.** Email стал обязательным и уникальным, при регистрации подтверждается письмом. Учётные записи без почты или с несовпадающим логином приводятся в порядок при обновлении — данные не теряются.
- Открытие туннеля к контроллеру стало заметно быстрее.

### Инфраструктура и развёртывание

- **Сертификат должен покрывать ещё и `*.apps.<домен>`** — без него облако не стартует. Нужна и DNS-запись: на этом поддомене живут веб-сервисы контроллеров.
- **Обновление одной командой `make upgrade`:** обязательный бэкап, проверка учётных записей на совместимость с новой схемой и только потом миграция. Пока данные не в порядке, миграция не запускается.
- **Хранилище метрик переехало с InfluxDB на TimescaleDB.** Накопленная история в новые графики не переносится: при обновлении она сохраняется в резервную копию рядом.
- **База данных работает в надёжном режиме.** Раньше запись велась с отключёнными гарантиями сохранности и без автоочистки — от такой конфигурации отключение питания могло стоить базы, а таблицы со временем распухали.
- **Почтовые настройки задаются отдельными переменными** (`EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`), а `EMAIL_ENABLED` нужно задать явно. Старые переменные `make upgrade` переносит сам.
- **Стек вырос** — добавились TimescaleDB, Grafana, Telegraf и два фоновых обработчика. Требования к серверу прежние: параллелизм фоновых задач по умолчанию рассчитан на сотню контроллеров и настраивается переменными в обе стороны.
- Появились настройки под своё железо и политику хранения: срок хранения метрик, параллелизм фоновых задач, геолокация сессий (см. `.env.example`).

## [1.5.0] - 2026-07-28

### Добавлено

- Переопределение ссылки «сайт компании» в футере веб-интерфейса через переменные `FOOTER_SITE_URL`, `FOOTER_SITE_LABEL_RU`, `FOOTER_SITE_LABEL_EN` (см. `.env.example`, секция Branding). Если переменные не заданы, используются значения Wiren Board по умолчанию.

### Изменено

- Заголовок вкладки браузера теперь берётся из `SERVICE_NAME`: для ребрендинга достаточно задать одну переменную. Переменная `HTML_TITLE` упразднена — если она задана в `.env`, она просто игнорируется.

### Безопасность

- Туннельный авторизатор: закрыты два обхода авторизации по `tunnel_key`. Модуль nginx `auth_jwt` теперь собирается из форка `wirenboard/ngx-http-auth-jwt-module` (2.0.2-wb3): зафиксирован алгоритм подписи JWT и вычищаются подменные claim-заголовки клиента.

## [1.4.0] - 2026-07-25

### Добавлено

- Переопределение названия продукта и ссылок в веб-интерфейсе через переменные окружения `SERVICE_NAME`, `HTML_TITLE`, `SERVICE_STATUS_URL`, `SERVICE_DOCS_URL` (см. `.env.example`, секция Branding). Если переменные не заданы, используются значения Wiren Board по умолчанию.
- Веб-консоль (webssh) теперь тоже использует брендовые ассеты из директории `branding/`: логотип и иконки подменяются так же, как в основном фронтенде.
- Веб-консоль (webssh) переопределяет название в заголовке вкладки и окне входа через `SERVICE_NAME`, а ссылку логотипа и редирект при ошибке туннеля — на домен инсталляции (`ABSOLUTE_SERVER`) вместо `wirenboard.cloud`.
- Переопределение цвета основной кнопки через переменную `PRIMARY_COLOR` (hex) в веб-интерфейсе и веб-консоли. Если переменная не задана, используется цвет по умолчанию.

## [1.3.0] - 2026-06-09

### Добавлено

- Полное отключение отправки email через переменную `EMAIL_ENABLED=False`: переменные `EMAIL_*` перестают быть обязательными, приглашения и сброс пароля выполняются через административную панель.
- Действие в административной панели для генерации одноразовой ссылки сброса пароля (работает без email).
- Документация: внешний reverse-proxy перед облаком (nginx и Traefik, L4 TCP passthrough); сетевая схема, порты и правила фаервола (`doc/SECURITY_NETWORK.md`, RU/EN); раздел об административной панели; развёртывание в локальной сети без публичного доступа (публичный сертификат + внутренний DNS).

### Изменено

- `EMAIL_ENABLED=True` теперь явно присутствует в `.env.example` (основная секция). Для существующих инсталляций ничего не меняется: если переменная не задана, отправка email включена, как и раньше.

### Исправлено

- Падение бэкенда на старте при пустом `EMAIL_URL`.
- Пример конфигурации nginx (маршрутизация по SNI): регулярное выражение не матчило корневой домен облака.
- Документация внешнего reverse-proxy: уточнено, что `your-domain.com` — это полный hostname облака, включая поддомен (значение `ABSOLUTE_SERVER`); для Traefik-примера (кейс C) добавлено предупреждение об экранировании бэкслешей в YAML-кавычках (ошибка `unknown escape character` приводит к отдаче default-сертификата вместо passthrough).
