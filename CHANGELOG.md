# Changelog

Все значимые изменения в проекте фиксируются в этом файле.

## [2.0.0] - 2026-06-06

> **Мажорный релиз с несовместимыми изменениями.** Данные пользователей **не
> удаляются** — они мигрируют на месте. Обновление выполняется командой
> `make upgrade`, которая **сначала делает обязательный бэкап** и **не запустит
> миграцию**, пока не устранены все конфликты учётных записей.

### Что меняется для пользователя

- **Вход теперь по email.** Email становится логином: обязателен и уникален (без
  учёта регистра). Учётные записи без email или с логином, не совпадающим с
  email, больше не допускаются — при обновлении они приводятся в порядок **без
  потери данных** (подробнее — в разделе для администратора ниже).
- **Изменился адрес регистрации.** Старый эндпоинт `/users-sign-up/` удалён (в
  upstream заменён на `/users/registrations/`); встроенный фронтенд обновляется
  синхронно, для пользователя страница регистрации продолжает работать.
- **История метрик за прошлый период не переносится в новые графики.** Хранилище
  метрик переезжает на TimescaleDB: старые данные InfluxDB **сохраняются в
  бэкап**, но в дашбордах Grafana метрики начинают копиться заново. Графики за
  период до обновления будут пустыми (исторические данные при необходимости можно
  поднять из бэкапа отдельно).

### Для администратора / DevOps

#### Обновление и сохранность данных

- **`make upgrade`** — управляемое обновление 1.x → 2.0. Порядок: обязательный
  бэкап (`pg_dump` + `influxd backup`, до любых изменений в БД) → проверка
  таблицы пользователей на конфликты → **остановка с выводом команды исправления,
  если конфликты остались** → `migrate` → запуск стека 2.0.
- **`migration_doctor`** (`migration/migration_doctor.py`) + **`make fix-users`**.
  Находит строки, нарушающие инварианты 2.0 (пустой/NULL email,
  `username != email`, дубликаты email), и исправляет их. Безопасные случаи
  исправляются автоматически (приведение email к нижнему регистру; устранение
  различий только в регистре/пробелах; email администратора из `ADMIN_EMAIL`).
  Остальное решается через **интерактивный мастер** либо через безголовый режим
  правки файла **`conflicts.yaml`** с последующим применением; оба режима
  валидируются (корректный email, отсутствие новой коллизии). Идемпотентно —
  можно перезапускать до 0 конфликтов.
- **`make backup`** — отдельный бэкап PostgreSQL + InfluxDB в `./backups`.
- Несовместимость на уровне БД вводит upstream-миграция `users/0013` (делает email
  уникальным логином) — она **без переноса данных**, поэтому заполненную базу 1.x
  и нужно привести в порядок перечисленными инструментами до миграции.

#### Инфраструктура

- **Бэкенд подключается к PostgreSQL напрямую** (`postgres:5432`). Пул соединений
  pgcat убран как избыточный для одноузловой поставки (пулинг/шардинг/разведение
  чтений — задачи upstream-HA, которых здесь нет).
- **Внутренняя конфигурационная БД Grafana** (дашборды/пользователи/организации)
  переведена с внешнего PostgreSQL на **встроенный SQLite** в `/var/lib/grafana`
  (том `clientsGrafanaData`). TimescaleDB остаётся **источником данных** метрик
  для Grafana без изменений.
- **Авторизатор туннеля** теперь читает публичный JWT-ключ бэкенда из
  **примонтированного файла** (`BACKEND_APP_PUBLIC_KEY_PATH`), а не из переменной
  окружения с содержимым PEM.

#### Удалено

- Сервис pgcat и его конфигурация (`pgcat/pgcat.toml`).
- Внешняя БД состояния Grafana: `postgres/init-grafana-db.sh` и переменные
  `GRAFANA_DB_NAME` / `GRAFANA_DB_USER` / `GRAFANA_DB_PASSWORD`. Переменные роли
  для источника данных теперь `GRAFANA_TIMESCALE_USER` /
  `GRAFANA_TIMESCALE_PASSWORD`.
- Переменная `BACKEND_APP_PUBLIC_KEY` (содержимое PEM) у авторизатора туннеля.

## [1.3.0] - 2026-06-04

### Изменено

- Хранилище метрик переведено с InfluxDB на TimescaleDB. Приём метрик от
  контроллеров теперь выполняет сервис Telegraf (HTTPS + mTLS, ограничение
  частоты запросов через Traefik), запись идёт в TimescaleDB. HA-обвязка
  upstream (Patroni, etcd, HAProxy, pgBackRest) для одноузловой поставки не
  используется — запускается один инстанс TimescaleDB.
- Воркеры Celery разделены по очередям: `worker` (default), `worker-metrics`,
  `worker-grafana`, `worker-email`.
- Обновлены версии образов: Redis `6-alpine` → `7.4.8-alpine`.

### Добавлено

- Сервис `clients-grafana` (Grafana 12.2.2) — пользовательские дашборды по
  организациям; хранит состояние в отдельной базе на bundled PostgreSQL.
- Сервис `tunnel-webhooks-backend` — отдельный инстанс бэкенда для обработки
  вебхуков FRP-туннелей.
- Сервис `postgres-backup` — ежедневный бэкап PostgreSQL в bundled MinIO (S3).
- Новые переменные окружения: `TIMESCALE_*`, `TELEGRAF_TIMESCALE_*`,
  `GRAFANA_DB_*`, `GRAFANA_ADMIN_*`, `METRICS_COLLECTOR_RATELIMIT_*`,
  `INTERNAL_LICENSE_SERVICE_TOKEN`, очереди `CELERY_*_QUEUE`, параметры бэкапа
  `POSTGRES_BACKUP_*` и опциональная интеграция с внешним Prometheus (`PROM_*`).

### Удалено

- Сервис InfluxDB и связанные переменные `INFLUXDB_USERNAME`,
  `INFLUXDB_PASSWORD`, `INFLUXDB_TOKEN`.
